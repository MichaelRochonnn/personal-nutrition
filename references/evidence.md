# 从书中主张到本次建议

1. 写下要解决的问题。包括对象（例如计划妊娠者）、地区、食物或干预、比较对象、目标结局（例如神经管缺陷或自然妊娠率）和时期。同一个“叶酸好不好”可以对应完全不同的问题。
2. 用主张 ID 找主体、关系、客体，读前提、数量、例外、来源和定位。单本著作对研究的转述保留“书中引用，原始证据尚未核验”。不要自行生成系统性证据等级；若来源确有分级，保留发布者、适用人群和原始指标。机制、观察关联、随机试验、指南推荐分别表述。
3. 查看冲突表及其全部成员。先对齐定义、可食部、生熟、每份重量、对照、地点、不同强度证据及年代。把仍成立的一部分与需要停用的执行结论分别写出。讨论证据时仍可展示历史观点；被隔离的数字与做法不得写进菜单或补充剂指令。
4. 对关键主张按实际执行日核对所属地区的发布机构，再按需查学会指南、系统综述或原始研究。有版本号、修订、替代或未来生效日期时一起记录。临床剂量、汞公告、食品召回、外卖价格等不能靠离线书目确定。来源冲突未消解时说明双方覆盖范围，必要时暂缓该项，给可行的餐食选择。
5. 按适用人群陈述：“在……条件下，该来源建议……；用于这份菜单的改动是……”。区分未研究、证据不足、已研究未发现益处、有反向证据和已知危险。

## 增量维护

- 添加书：新建来源 ID、作者、版本、语言、文本指纹及定位约定。按章更新阅读覆盖；先登记无法辨认处。保留原书在用户自己的位置，分享包只保存必要摘要、索引与定位。
- 添加或修订主张：在对应的 *-claims.jsonl 中追加新 ID；实质性修订保留旧行，给旧行加 lifecycle = superseded 或 withdrawn，新行填 supersedes（旧ID数组）。记录证据类型、核查日与冲突/支持关系。追加 relations.jsonl 和 changes.jsonl，写明原因、受影响主张/食谱及需复测场景。日期格式 YYYY-MM-DD。过期资料在 show 中保留，搜索默认不作为候选。来源版本变更保留原来源文件记录，给新版本独立 ID。
- 运行 python3 scripts/graph.py build，再 validate，并复跑 tests/verify.py。核对图中变化与原始定位。若在工作副本更新，验证后同步安装副本，先备份已有版本。版本由变更记录标识。
- 个人喜好、执行反馈、症状与偏差只记录在获授权成员的私有档案；将不喜欢豆腐写成菜单偏好即可。要改变科学主张仍须新证据。更新包时检查不含成员档案、书籍或识别出的整页原文。
