# 把主张变成一餐

**首次调用。** 若只想知道“咖啡算饮水吗”，直接查概念、对象与来源；无需问身高。若要家人共餐，先列成员、习惯食量、谁有何限制、谁需要额外搭配。没有年龄、严重过敏是否存在、妊娠角色等必要条件时，先给可用框架，问最少的关键问题。是否需要精确能量取决于目标与可用数据。区分“未知过敏史”与“本人确认无已知过敏”。

**一餐与一天。** 从实际主食和份量出发，配一份或两种蔬菜、一种可吃的蛋白质来源。把水果、奶或合适的替代品放在方便的餐次。餐盘、宝塔的日均量在数天中评估；单餐可以相应多或少。年龄、活动量、胃口、咀嚼能力和做饭条件一起决定起始量。训练较多时确认项目、时长及餐距；专业耐力补给或疾病管理另查。围绝经期检索 EXT-026，老年食欲下降检索 EXT-025，哺乳检索 EXT-027，孕期食品检索 EXT-018/019。先问变化，不能沿用备孕产品或以前的能量安排。

**一周与购物。** 先安排难保存的原料，谷物、鸡蛋、可耐受豆制品和应季蔬菜跨餐复用。用时间最紧的一天倒推搭配。与用户对齐“20分钟”是全天还是每餐、含不含等候，默认实际总耗时包含清洗切配和烹调；事先解冻、周末备餐、外卖送达另列。无提前准备时优先即食主食、薄切食材，不能把煮生糙米塞进15分钟。剩菜的冷却、分装、复热见 EXT-016/017，生鸡处理查 EXT-030。采购清单列食谱净用量及状态。要声称预算满足，需用户提供单价或查同地同日的实际购买规格、币种、可食率、库存和配送；估算整包成本，余料记库存。超支优先调换季节蔬菜和可耐受的蛋白来源。不要将示范价格用于报价。

**旅行。** 先看地区、酒店早餐、冷藏设备温度是否可信、能否洗果蔬、附近获取渠道和当天行程。在酒店选现做热蛋、热主食和整果；机场/高铁备独立常温饮品、完整水果和有标签的主食，肉蛋奶制品依标示储存；便利店按是否可直接食用来买；外卖和餐馆点现做主食、蔬菜和核实做法的主菜，酱汁另装。没有可靠冰箱便按餐采购，剩下的易腐品不带到下一餐。询问餐馆对具体过敏原、共锅、夹具与炸油的处理；无法确认则换成可核的独立包装或别家。具体菜单、门店营业、库存及价格需要可查的当日信息。

**替换与家庭。** 先说被替换食材的作用（结构、主食、蛋白、某一营养素、风味或成本），再说保留与改变了什么、每人起始量和重量口径。用 [食材与替换表](substitutions.jsonl) 检索替代；按成员排除过敏、宗教限制、口味与医嘱，换后重查酱料、配菜、交叉接触与时间。牛奶过敏禁用无乳糖牛奶，乳糖不耐受则取决于个人耐受；花生并非所有坚果，鱼类、甲壳类、软体动物分别核对。无把握时避开未知成品。共同备孕的叶酸公共卫生信息只对计划妊娠者适用，核对产品与用药；另一成员可共享饮食原则，无证据给双方开同款助孕补充剂。共同底菜需对所有吃它的人可用，分餐后才能加个性化配料；有交叉接触风险时优先全程选可共用的食材。

**记录、照片与标签。** 文字/照片先描述可观察部分，缺乏比例尺时用“约半碗”等范围，并写明隐藏油盐、汤底、剩余量未知。必要时只追问最影响结论的一项。用几天的饥饱、精力、接受度、实际开销/耗时与采购困难选一到两处调整；不给单张照片精确热量、过敏放行或疾病判断。标签先识别地区、日期、份量、整包重量、配料（含复合成分）、过敏提示、每100 g/mL或每份、食用状态。调水体积、油盐酱料和实际吃下多少要一致。若仅知道一个营养素，只算这一项；照片不清时询问对应字段。营销说法写出食物、量、对象、比较、终点、来源。将“排毒”“抗炎”“超级食物”拆成可验证的问题，标出证据范围、可能风险、缺少的数据。没有研究支持属于证据不足。

**有多个禁忌或临时换菜时**，可运行 `python3 scripts/review_menu.py -`，从标准输入读本次已确认的最少信息，不写入技能目录。成员使用空白档案中的 member_id、current_stage、confirmed_at、allergies_and_cross_contact（名称数组）、other_exclusions（硬性忌口名称数组）；未知用 null。输入 dishes 按菜列 eaters、planned_stage、components、all_components_included 和 kitchen_checked_for。每个配料填 name、contains、cross_contact、verified_for、basis。verified_for 只填已从当前包装、供应方或厨房实际确认过的限制；输入前把食材衍生物、复合配料拆开，定义不明确的过敏原问本人。本工具检查申报资料中的冲突；缺乏核实信息时保留“待核”。每次替换后用完整新菜和全部相关成员重跑。口味偏好在选菜时另行处理；按个人意愿严格排除的食材列入硬性忌口。示例见 ../tests/verify.py。

检查输入可传本次 as_of（YYYY-MM-DD）；旧日期字段须由该成员本次确认后列入 reconfirmed_for_this_plan，或更新 confirmed_at。不要为通过检查自行填写这些值。组件的 contains、cross_contact 填核实过的名称列表，未知保留 null。输出“已通过所列条件检查”仅表示申报内容与所列限制之间未发现矛盾。
阶段特定的菜把 stage_sensitive 置为 true，planned_stage 逐人填写。若报告只有“海鲜”“坚果”“乳糖过敏”等笼统叫法，须澄清具体过敏原；成分过于复杂或本工具没有编码的过敏交叉反应由适格人员核对。把营养计算和过敏检查分开做。
